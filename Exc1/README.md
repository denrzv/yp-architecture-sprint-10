# Аудит мер по обеспечению безопасности данных

На данный момент:
1. Данные хранятся в локальной инфраструктуре (Excel, общий диск (файловый сервер), системы 1С).
2. Используется файловый режим 1С.
3. Нет механизмов шифрования данных на уровне хранилища (Excel, файловый сервер).
4. Доступ к данным осуществляется через доменную аутентификацию в Active Directory, однако:
* Отсутствует разграничение прав доступа на уровне файлов и систем.
* Логирование и аудит доступа к данным отсутствуют.
5. Внутренние потоки данных между системами (Excel ↔ 1С ↔ файловый сервер ↔ ККМ) не защищены. Нет межсистемного контроля передачи данных.
6. Нет механизма аудита изменений.
7. Положения законодательства РФ 152-ФЗ явно не соблюдаются, что создает риск штрафов и потери доверия клиентов.


# Сопоставление процессов с требованиями безопасности

Общие требования:

* Шифрование персональных данных (PII) в хранилищах и при передаче.
* Ограничение доступа к PII и ведение журнала доступа.
* Обеспечение резервного копирования и восстановления.
* Регулярный аудит системы защиты.
* Минимизация данных (собирать только те данные, которые необходимы).
* Обезличивание и псевдонимизация персональных данных.
* Принципы Privacy by Design и Security by Design.
* Использование защищенных протоколов (HTTPS, TLS).
* Логирование всех действий и доступов.
* Настройка RBAC или ABAC.
* Мониторинг и автоматизация безопасности.

Список проблемных зон:

| Зона                             | Проблема                                                                                       | Последствия                                                              |
|----------------------------------|------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------|
| 1. Хранение данных               | Нет шифрования хранилищ (Excel, файловый сервер).                                              | Утечка данных, нарушение 152-ФЗ.                                         |
| 2. Контроль доступа              | Нет разграничения доступа на уровне пользователей, нет RBAC/ABAC                               | Несанкционированный доступ сотрудников к конфиденциальным данным.        |
| 3. Перемещение данных            | Данные передаются между системами без шифрования или контроля.                                 | Утечка данных при передаче, пересылка на внешнюю почту - облачный диск.  |
| 4. Логирование и аудит           | Нет логирования действий с конфиденциальными данными.                                          | Невозможно определить источник утечки или нарушения.                     |
| 5. Защита PII                    | Отсутствие обезличивания/псевдонимизации данных пациентов.                                     | Нарушение требований 152-ФЗ, возможность прямой идентификации пациентов. |
| 6. Учет изменений                | Нет системы контроля версий и аудита изменений в файлах Excel и базах 1С.                      | Потеря целостности данных, сложность восстановления в случае ошибки.     |
| 7. Инфраструктурная безопасность | Локальный сервер находится в офисе компании, без резервной площадки или защищённого периметра. | Потеря данных при физическом повреждении.                                |
| 8. Поддержка роста данных        | Отсутствует масштабируемая архитектура для хранения данных.                                    | Проблемы с производительностью при 5-кратном увеличении объёма данных.   |

# Cписок данных для защиты

| Категория данных              | Примеры                                                        | Меры защиты                      |
|-------------------------------|----------------------------------------------------------------|----------------------------------|
| Персональные данные (PII)     | ФИО, дата рождения, номер телефона, адрес проживания.          | Шифрование, обезличивание, RBAC. |
| Медицинская информация        | История болезни, результаты анализов, хронические заболевания. | Шифрование, обезличивание.       |
| Финансовые данные             | Сумма платежей, данные чеков, информация из 1С.                | Шифрование.                      |
| Контактные данные             | Электронная почта, телефон.                                    | Шифрование, обфускация.          |
| Учётные данные сотрудников    | Логины, пароли, роли сотрудников.                              | Хэширование, RBAC.               |
| Документы                     | Скан-копии паспортов, PDF-файлы.                               | Шифрование.                      |
| Товарно-материальные ценности | Данные о закупках, поставщиках, складах.                       | RBAC.                            |
| Системные данные              | Логи доступа, детали работы приложений.                        | Логирование, шифрование.         |

#  Разработка механизма тегирования данных

Необходимо проработать систему тегирования:

1. Классифицировать данные. Теги будут указывать на уровень чувствительности данных.
2. Автоматизировать обработку данных. Теги будут использоваться для применения политикзащиты данных.

| Тег       | Описание               | Пример данных                | Применяемые меры              |
|-----------|------------------------|------------------------------|-------------------------------|
| PII       | Персональные данные.   | ФИО, дата рождения, телефон. | Шифрование, RBAC.             |
| MEDICAL   | Медицинские данные.    | Диагноз, история болезни.    | Шифрование, обезличивание.    |
| FINANCIAL | Финансовая информация. | Чеки, суммы платежей.        | Шифрование, RBAC.             |
| INTERNAL  | Внутренние данные.     | Метаданные систем. Рабочая информация | Шифрование, логирование.      |
